# Working Rules

1. Do not rush implementation before the current phase contract is clear.
2. Use V3.2 as the authority when a business-rule dispute arises.
3. Do not over-engineer with Kafka, Kubernetes, microservices, a data warehouse, or an external feature store without real need.
4. Every phase requires deliverables, acceptance criteria, and a gate.
5. Schema/contract checks are not runtime proof; implementation requires integration, concurrency, and security tests.
6. Do not freeze curriculum, mastery logic, adaptive paths, or the final risk label before the Learning Intelligence phase.
7. Do not distort the product to preserve old research feature counts/models.
8. Production models must be evaluated on product-generated data.
9. The learning product must remain usable with ML/recommendation disabled.
10. Important new decisions should be added to the project progress snapshot.
