# Qualitative usability protocol — NOT RUN

Purpose: understand whether the intended learners can start, practice, interpret feedback/progress and recover from offline states without developer help. About5 adult Vietnamese learners across lower/higher digital confidence, plus a separate small staff cohort for author/reviewer workflows. Recruit consented participants, not coworkers instructed to praise the app. Include accessibility needs where recruitment supports them; five is exploratory, not representative or statistically powered.

Before: explain fixture boundary and absence of real scoring/account/publishing. Obtain separate consent for participation, audio/screen recording and anonymized quotes. No real learner records, password, school/medical status or unnecessary identity. Participation voluntary, stop anytime without loss. Coordinator stores coded IDs, separates consent/contact from notes, restricts access and deletes recordings after agreed30days; consent policy requires organizer approval before recruitment. No messages/recruitment sent by this task.

Session40–50min:5min consent/context;25min tasks with think-aloud;10min debrief;5min wrap. Moderator says “Please say what you expect and what you are looking for”; avoid hinting the control. If blocked, record attempt then neutral prompt; assisted completion stays separate from unassisted.

| Task | Observable outcome |
|---|---|
| Open Mingo, skip setup if desired, start one lesson | Finds Home primaryaction, understands estimated time |
| Choose goal, return and change it | Recognizes optional/reversible choice |
| Answer wrong, explain feedback, use hint/retry | Distinguishes first answer and supported practice |
| Reach Check | Understands no hint/retry; can leave |
| Explain result/progress in own words | Does not infer mastery from habit/sample counts |
| Find downloaded lesson with unavailable network | Distinguishes ready asset from pending send |
| Read partial sync/revision/audio failure | Knows safe next action without false success |
| Preview a locked objective | Understands preview vs eligibility |
| Staff: find learner evidence/activity | Separates evidence/time/source from risk |
| Staff: edit draft, review license, confirm, new draft | Understands immutable revision and fixture boundary |

Observation form: participantID/taskID; start/end; firstclick; expectation; path; errors; completion{unassisted,assisted,failed}; exact quote(optional); confusion; moderator prompt; severity{P0data/rights lie,P1core blocked,P2friction,P3cosmetic}; proposed correction; retest owner. Do not turn elapsed time or5ratings into population percentages. Look for repeated issues and counterexamples, retain minority/a11y issues even if one participant reports them.

Debrief: What would you do next? Which result did you trust and why? What is saved on the device vs confirmed by system? What felt like pressure? What felt unnecessary? Describe mascot/tone without leading them. Ask perceived effort1–5 only as a qualitative prompt. Report observations, limitations and actual attendance; do not backfill missing consent or PASS. Iterate and run another round after changes. Human product signoff stays separate.
