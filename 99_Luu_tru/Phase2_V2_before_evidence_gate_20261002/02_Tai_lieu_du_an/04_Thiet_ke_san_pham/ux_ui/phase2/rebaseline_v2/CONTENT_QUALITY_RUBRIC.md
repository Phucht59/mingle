# Content quality rubric

Review before a revision can be published; UI fixture checks demonstrate the path, not real reviewer authority. Each criterion: 0=missing/blocking,1=needs correction,2=ready with inspectable evidence. No average can compensate for any blocking criterion. Assign author and independent reviewer; retain evidence and revision ID. Human/content expert review pending.

| Criterion | Required evidence / rejection condition |
|---|---|
| Objective | One observable action, target language level/context; reject vague “learn English” |
| Linguistic accuracy | Correct answer, plausible distractors, dialect/context note; reject ambiguity |
| Retrieval | At least one independent question; do not count exposure/skip as recall |
| Transfer | Different prompt/context, same objective; no claim of broad real-world transfer from one MCQ |
| Feedback | Explains why, task-specific, kind; no ego label or punitive result |
| Review spacing | Due reasoning matches authoritative schedule; no invented optimal gap |
| Assisted evidence | Hint type and practice retry separate; first response retained; Check prohibits hints/retries |
| Challenge/prerequisite | Exact frozen rule: two distinct unaided first responses, including Check; preview never unlocks |
| Duration | Metadata estimate (e.g. around5min), measured in pilot later; no scientific optimum claim |
| Media | Licensed file, transcript/alternative, locale; fail unavailable listening audio rather than guess |
| License/source | Creator, URL/source, license scope, attribution, capture date, reviewer; unresolved blocks publish |
| Accessibility | Scalable text, semantic question/options, text alternatives,48dp and contrast |
| Age/culture | Audience appropriate, non-stereotyping, no medical/early-risk diagnosis |
| Revision integrity | Published revision immutable; attempts pin exact revision; edit creates a draft |

Example draft: “Chào hỏi và làm quen”; independently written miniature greeting questions. This sample is a UI illustration and requires content review before production. All 0/1 items return to author with a correction note; do not auto-publish with model output. Do not convert the rubric into a new backend/schema rule in this Phase2 task.
